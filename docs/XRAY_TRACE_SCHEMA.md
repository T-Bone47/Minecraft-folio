# FRONTIER X-RAY: TRACE SCHEMA SPECIFICATION
## Canonical Observability Format & Provenance Standards

---

## 1. Trace Record Specification (`TraceRecord`)

Every trace collected in the Reality Engine conforms to the strict `TraceRecord` interface.

```typescript
export interface TraceRecord {
  /** Unique execution trace identifier (e.g. trace_1731456000000) */
  traceId: string;
  /** Browser / session identifier for correlation */
  sessionId: string;
  /** ISO-8601 UTC timestamp of trace initiation */
  startedAtIso: string;
  /** Primary engineering subsystem owning the root execution */
  subsystem: XRaySubsystem;
  /** Certified provenance declaration */
  provenance: ProvenanceType;
  /** Human-readable trace title */
  title: string;
  /** Technical description of operations performed */
  description: string;
  /** Ordered array of causal execution spans */
  spans: TraceSpan[];
  /** Discrete timestamped checkpoint events */
  events: TraceEvent[];
  /** Total elapsed time in milliseconds */
  totalDurationMs: number;
}
```

---

## 2. Span Hierarchy & Field Definitions (`TraceSpan`)

```typescript
export interface TraceSpan {
  /** Trace correlation ID */
  traceId: string;
  /** Unique span identifier within trace (e.g. span_veh_sim) */
  spanId: string;
  /** Causal parent span ID (null for root spans) */
  parentSpanId: string | null;
  /** Technical operation name (e.g. "Distance-Aligned Interpolation") */
  name: string;
  /** Subsystem domain */
  subsystem: XRaySubsystem;
  /** Facility location where operation occurs in campus */
  facilityId: string;
  /** Monotonic high-resolution start time in milliseconds */
  startTimeMs: number;
  /** Monotonic high-resolution end time in milliseconds */
  endTimeMs: number;
  /** Duration in milliseconds (endTimeMs - startTimeMs) */
  durationMs: number;
  /** Execution status */
  status: "success" | "warning" | "error" | "running";
  /** Sanitized snapshot of input parameters */
  inputSummary: Record<string, unknown>;
  /** Sanitized snapshot of output results */
  outputSummary: Record<string, unknown>;
  /** Optional error diagnosis when status is 'warning' or 'error' */
  errorClassification?: string;
  /** Provenance of the executed code */
  provenance: ProvenanceType;
  /** Direct link to source file, symbol, and verification test */
  sourceRef: SourceReference;
  /** Additional technical tags */
  metadata?: Record<string, unknown>;
}
```

---

## 3. Provenance Certification Types (`ProvenanceType`)

To prevent ambiguous or misleading claims, all spans and traces must declare one of the following canonical provenance types:

| Provenance Level | Description |
|---|---|
| `ACTUAL_RECORDED_EXECUTION` | Live execution captured in real time from the visitor's browser session (e.g. real laps driven on track). |
| `DETERMINISTIC_REPLAY` | Pure analytical algorithms replayed deterministically from verified seed parameters with identical outputs. |
| `SIMULATOR_TELEMETRY` | Telemetry generated by the 50Hz kinematic vehicle physics simulator running in the browser. |
| `BUNDLED_TEST_FIXTURE` | Reference telemetry collected under official benchmark conditions, packaged for instant audit. |
| `VERIFIED_HISTORICAL_DEFECT` | Real software defects and bug fixes extracted from the project's Git commit history with before/after diffs. |

---

## 4. Source Reference Anchors (`SourceReference`)

Every span links directly to its authoritative code location:

```typescript
export interface SourceReference {
  /** GitHub repository (e.g. "T-Bone47/Minecraft-folio") */
  repo: string;
  /** Relative file path within repository (e.g. "lib/digitalTwin/analysis.ts") */
  file: string;
  /** Function, method, or class name (e.g. "performCompleteLapAnalysis") */
  symbol: string;
  /** Test file verifying the implementation */
  testFile?: string;
  /** Exact line range in source */
  lineRange?: [number, number];
  /** Verified git commit hash */
  commitHash?: string;
}
```
